# Retro: doors and the game loop so far (2026-10-05)

Covers doors D1-D4 and game loop G1-G2b (commits 318b0f5 to 9eb54ce).

## What went well

- Rules came from KF's scripts and class defaults first (doors, welding,
  wave tables, spawn volumes), with numbers checked in logged runs. Most
  steps worked on the first logged run.
- Splitting steps when they grew (D3 into D3a / D3b, G2 into G2a / G2b)
  kept each commit small and revertable.
- Research agents for the large scripts (KFGameType waves, the trader)
  saved time; their numbers matched what the code later read from data.
- Your play-testing found what logs did not: the staircase in front of the
  KF-Manor test door, the KF-WestLondon fence.

## What went wrong, and why

1. **A map feature looked like an AI bug.** Zeds stuck at the
   KF-WestLondon fence: the pocket is meant to be left by a jump pad,
   which we did not simulate, and by jump links we dropped. Cause: no
   inventory of what the maps contain versus what we simulate.
   Fix: this audit (`docs/map-audit.md`) and the `map_features` log line
   at every map load.
2. **Stale assumptions in code.** Jump links were left out because "our
   zeds cannot jump yet"; zeds learned to jump later and the filter stayed.
   Several other comments were out of date (the Welder "no doors", zed.rs
   "no pathfinding, no damage"). Fix: comments corrected; when a feature
   lands, search the code for "yet" / "not done" mentioning it.
3. **A wrong "clippy clean".** I filtered clippy's output for lines
   starting with `warning`, which the output wrapper had reshaped, and
   reported clean while three warnings existed. Fix: read clippy's own
   summary line ("No issues found") instead.
4. **Test setups chosen blind.** The M79 test fired into steps in front of
   the door. Fix: check the ground along a test line (walk logs give the
   height) before using it.
5. **Native engine behaviour guessed.** Several rules live in the engine,
   not the scripts: jump pad launch point, SetLocation's free-spot search,
   Spawn's fit test, LastRenderTime, distance fog. Each is labelled as an
   approximation in DESIGN; the SDK you installed has only scripts, so
   these stay approximations.
